## Что сейчас вычисляет границы и что расширяет покрытие

ARCore владеет единственной камерой; MediaPipe Face Landmarker выдаёт outer/inner lip contours. Model-independent adapter/display transform → LipContourTemporalRefiner → LipMeshTessellator → material/mask. Основной non-blocking Sync использует exact camera/geometry pair; не менять accepted Sync/стабильность без доказанной причины. После исправления tessellator дополнительно сохраняет measured outer arcs до expansion и пишет per-vertex pixel distances; renderer копирует их сразу, перед linerMesh.update, который повторно использует тот же tessellator. Не откладывать копирование после этого повторного tessellate.

Landmarks/topology/mapping/refiner не переписывались. Прежние carrier positions помады СОХРАНЕНЫ: outer0.18; inner seam0.14 закрытый/0.10 открытый с адаптивным feather; уголки outer-only0.012 ширины рта с затуханием в крайних12% дуги. Эти коэффициенты не означают более точного определения натуральной границы. После исправления финальный outer feather помады общий для тела/уголков и считается по signed distance до исходного outer contour (AA1–2px), прежняя corner feather0.10 удалена. Карандаш использует те же refined contours БЕЗ carrier expansions, с contour-anchored профилем, прежним blur и corner fade; inward inset/preclip/широкий post-blur outer reclip больше не действуют. Их masks по-прежнему разные, landmark input общий.

Для следующей диагностики разделять: raw landmarks → transformed/refined contour → render carrier → фактический край alpha. Желательно получить одинаковую позу без обоих материалов, только с карандашом, только с помадой и «Копию» настроек. Пока нельзя уверенно приписать замечание tracker или blur.

Новая локальная проверка полноты:6 статичных синтетических форм (ширина256px, outer height35.84/71.68/143.36px, закрытый/открытый рот), compiled refiner/base tessellator сохраняют заданные outer/inner knots с ошибкой0px;18 offscreen GLES captures подтверждают увеличение пиксельной ширины мягкого перехода при росте полноты. На50% собственного пика alpha нижний край карандаша расположен внутри заданного контура на2.98→7.42px, помады при закрытом рте1.98→4.42px. Это условный alpha threshold, не измерение реального зазора; помада сохраняет примерно0.31–0.33 alpha на заданном outer contour. Общая геометрическая ошибка на реальном лице с полными губами ещё не воспроизведена. ### Проверка избыточной яркости сатина

Пользователь сообщил, что Android-сатин слишком яркий, и подтвердил сравнение с тем же B8202D; скриншот iOS предоставить не может. В iOS-копии сохранённых изображений-эталонов нет. Причина субъективной разницы пока не доказана; первый перенос не принят.

Обнаружено отличие финального композитинга: iOS формирует sRGB-tagged CGImage для SceneKit, Android смешивал correctiveColor и camera RGB непосредственно в sRGB. В IosSatinLipMaterial добавлены отдельные кусочные sRGB transfer functions (12.92 / 0.04045 / 2.4 / 0.0031308), финальный alpha blend выполняется в linear light с обратным кодированием. Формула самого Metal-пигмента остаётся в исходном sRGB; B8202D, плотность 0.92, opacity 0.99, блики и geometry/coverage не менялись. Это исправление этапа переноса, не произвольное затемнение и не доказанное решение жалобы. Linear blending может повышать светлоту отдельных каналов; нужно оценить насыщенность/общий вид на устройстве, не обещать уменьшение численной яркости.

Оценка ARCore lighting в текущей Activity явно DISABLED. Прежний вывод уточнён: iOS multiply 0.90–1.0 относится только к CPU fallback; при Metal SceneKit factor=1. Согласование camera input/detail/color chain остаётся открытым. Подставлять ×0.90 без измерений нельзя.
